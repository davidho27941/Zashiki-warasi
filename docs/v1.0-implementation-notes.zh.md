# v1.0 Implementation notes — 實際跟原設計的落差

> 中文版。English original: [`v1.0-implementation-notes.md`](v1.0-implementation-notes.md)
>
> [`v1.0-smoke-lessons.md`](v1.0-smoke-lessons.md)(+ [中文](v1.0-smoke-lessons.zh.md))
> 記的是**部署時期什麼壞了**;這份記的是**v1.0 出貨版跟原本設計有哪裡對不上**。
> 兩份都是 Proxmox docker + k3s Helm smoke 收工後寫的,讓未來讀 release
> 的人不會把「凍結的設計文件」誤讀成「實際跑起來的樣子」。

以下每條都是 bug fix 或途中微調,不是 scope 變更 —— scope 有變的話會另開 openspec proposal。設計意圖的 source of truth 是 `migrate-to-fastapi-service` OpenSpec change(本機保存,PR merge 後 archive 到 `openspec/changes/archive/2026-08-XX-migrate-to-fastapi-service/`)。

## Env var prefix:是 `GMAIL_*` 不是 `GOOGLE_*`

Design D7 和 spec 初稿都寫 `GOOGLE_CREDENTIALS_PATH` / `GOOGLE_TOKEN_PATH`。但 code 端一直都是 `GmailSettings.env_prefix = "GMAIL_"`(v0.6.x 沿用),實際 env var 是 `GMAIL_CREDENTIALS_PATH` / `GMAIL_TOKEN_PATH`。Deploy templates 一開始照 spec 寫成 `GOOGLE_*`,第一次 docker smoke 時 container fallback 到預設 `credentials.json` 找不到檔案 → crash 才抓到。

- [`de55a2d`](../commit/de55a2d) 修 —— Dockerfile ENV、`.env.example`、docker-compose.yml、Helm values.yaml、MIGRATION-v1.md 全部改回 `GMAIL_*`。
- 這個 change dir 的 specs (`specs/*.md`) 也回溯修正,確保 sync-to-main-specs 不會傳播錯 prefix。
- design.md 保留 `GOOGLE_*` 原文當作歷史紀錄。

## Container entrypoint 在 uvicorn 前跑 `alembic upgrade head`

Design D5 說了 Dockerfile 的形狀但沒指定 migration entrypoint。v0.5 那個 Dockerfile 有,但我把 `alembic.ini` + `alembic/` 排除掉了(`.dockerignore`),而且忘記加 COPY 或 entrypoint hook。

Proxmox smoke Phase 5.1 抓到 —— 新開的 `zashiki_v1_smoke` DB 第一次 tick 就 `UndefinedTable`。

- [`10f6327`](../commit/10f6327) 修 —— 新 `docker-entrypoint.sh` 對 `$DATABASE_URL` 跑 `alembic upgrade head` 然後 exec CMD。Alembic 的 `alembic_version` row-lock 讓多 replica 同時啟動時 concurrent 安全。

## Helm Deployment 加 init container 來 seed `token.json`

Design D7 說 "token.json ... read-write mount that survives container restarts",但 Helm chart Deployment 的 volume 只 mount 了 `credentials.json`。`token.json` 進了 Secret(`oauth.tokenJson`)但沒 mount 到任何 app 可讀的位置。

Helm smoke 抓到 —— 第一個 pod crash,`webbrowser.Error: could not locate runnable browser`,因為 `get_credentials()` fallback 到 `InstalledAppFlow.run_local_server()` 但 container 裡沒瀏覽器。

- [`8c497a1`](../commit/8c497a1) 修 —— 新 `oauth-seed` volume mount 整個 Secret 到新的 `seed-token` init container,由它在首次啟動時把 `token.json` 複製到 PVC。guard 避免覆蓋 in-cluster `/reauth` 寫的 token。

## `OAUTHLIB_RELAX_TOKEN_SCOPE=1` 無條件開

Design D8 討論 PKCE + FastAPI 中介 flow,但沒預期到 Google token endpoint 會回**該 user/client 對曾授權過的所有 scope** —— 通常是這次請求的 superset。oauthlib 預設嚴格 scope-equality check → 拒絕。

Proxmox smoke Phase 5.2 抓到。當時的 OAuth client 過去授權過 Drive scope,reauth 的 token 就把 Drive 一起帶回來 → `fetch_token_failed: Scope has changed`。

- [`7fcb953`](../commit/7fcb953) 修 —— `OAUTHLIB_RELAX_TOKEN_SCOPE=1` 在 Dockerfile ENV **AND** `core/services.py` 的 `os.environ.setdefault(...)`(oauthlib import 之前)。container 跟 CLI runtime 都 cover。

## PKCE `code_verifier` 存進 OAuth flow store

Design D8 描述 flow store 存 `client_config`, `_scopes`, `_redirect_uri`, `_state`, OAuth session token if any —— 漏了 `code_verifier`。google-auth-oauthlib 的 `Flow.authorization_url()` 會自動產 PKCE verifier 存在 Flow instance 上;callback 時重建的 Flow 有全新的 verifier,對不上 Google 從 `/auth/start` 看到的 challenge。

Proxmox smoke Phase 5.2 抓到:`fetch_token_failed: (invalid_grant) Missing code verifier`。

- [`cfab222`](../commit/cfab222) 修 —— `OAuthFlowStore._serialize` 存 `flow.code_verifier`;`_reconstruct` 還原。regression test 在 `tests/coordination/test_oauth_flow_store.py::test_roundtrip_preserves_pkce_code_verifier`。
- `specs/headless-authentication/spec.md` 那句 "Flow serialization: ... SHALL be extracted to JSON" 保留原文 —— `code_verifier` 就是「reconstructable state」現在該包含的欄位之一;code + regression test 才是 truth。

## Helm chart 支援私有 registry 的 `imagePullSecrets`

原設計跟 specs 都沒寫 —— 初版 chart 假設是 public image(Docker Hub / 公開 GHCR)。smoke 中途要部署到自建 GitLab registry(`gitlab.davidho.dev:5050`)才加。

- [`d7ddfec`](../commit/d7ddfec) 加 —— `imagePullSecrets` value 預設空 list(no-op),用私有 registry 的 operator 自己填。Deployment 跟 CronJob 都吃這個 value。

## RWO ↔ replicaCount 相容契約

Design D17 說 `replicaCount > 1` 安全,但 Helm chart 預設 `persistence.accessMode: ReadWriteOnce` —— 這在 multi-node 環境會擋 scale-up(`MultiAttach error`)。相容契約原本是 implicit,現在 `values.yaml` 明確寫。

- [`77923b7`](../commit/77923b7) 修 docs。沒改 code;預設保留 RWO(通用相容);要 multi-replica 的 operator 必須改 RWX 且 storage class 要支援。

## Longhorn RWX 前置:每個 node 都要 nfs-common

不是 chart 問題 —— 但 Helm smoke Phase E 抓到,對 operator 夠重要就寫進 doc。Longhorn RWX 用 NFS(share-manager)實作;每個跑 RWX pod 的 node 都要有 `nfs-common`(Debian/Ubuntu)或 `nfs-utils`(RHEL/CentOS)。

寫在 `docs/v1.0-smoke-lessons.md` issue #12。

## Host cron 的坑(`%` 逃逸 + shell env)

設計沒提,因為「外部 cron 驅動 cadence」是比較 high level 的描述。Proxmox smoke Phase 6 遇到兩個:未逃逸的 `%{http_code}` 讓 cron 悄悄截斷 command;crontab 內的 `${HTTP_API_KEY}` 執行時是空的,因為 cron 不 source shell profile。

- [`9ba2b32`](../commit/9ba2b32) 修 —— `crontab.example` 逃逸 `%` 且教「把 key 值直接貼進去」,坑寫在檔案 header。

## Postgres UTF-8 encoding 是硬性需求

`_persist` 寫中文 JSON 到 `email_analyses.keywords`。`SQL_ASCII` encoding 的 DB(某些系統 `template1` 預設)會 crash,`psycopg.errors.UntranslatableCharacter`。這其實不是設計問題 —— v0.6.x prod DB 剛好 UTF-8 —— 但 smoke 新建的 test DB 沒指定 encoding。

- 沒 code 修(operator side DB provisioning)。寫在 MIGRATION-v1.md troubleshooting appendix + README Requirements。
- 未來改進(未出貨):`build_services` 開機時 `SHOW server_encoding`,不是 UTF8 就拒絕啟動。

## Test 數

原本 tasks 預期新測試模組在 `tests/web/`、`tests/coordination/`、`tests/auth/`(task 17.1)。實際 layout 是 `tests/web/` + `tests/coordination/` + `tests/deploy/`(env parity + Helm chart lint)—— 沒獨立的 `tests/auth/`,auth 測試在 `tests/web/test_auth.py`。

最終 unit test 數:559 passing(v0.6.0 baseline 476)。smoke 期間加 1 個 regression pin(PKCE);其他 +82 是 6 個 authoring session 累積的。
